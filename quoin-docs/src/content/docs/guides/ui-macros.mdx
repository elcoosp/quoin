You will replace hand-written framework view code with Quoin's declarative macros. One syntax expands to native code for your chosen framework: a `Render` impl on GPUI, a `#[component]` function on Leptos and Dioxus.

**Prerequisites:** the `macros` feature (implied by any framework feature) — see [Installation](/guides/installation/).

## Define a component with `component!`

`component!` declares props, reactive state, globals, lifecycle hooks, actions, and the render tree in one block:

<Code lang="rust" code={"use quoin_macros::component;\n\ncomponent! {\n    pub DemoApp {\n        props {\n            initial_count: u32 = 0,\n        }\n        state {\n            count: u32 = initial_count,\n            selected: String = \"Option A\".to_string(),\n        }\n        globals {\n            theme: Theme,                  // automatically retrieved from context\n            router: RouterState observe,   // observe = track changes\n        }\n        on_mount {\n            log::info!(\"Component mounted\");\n        }\n        on_unmount {\n            log::info!(\"Component unmounted\");\n        }\n        fn increment() {\n            count.update(|c| *c += 1);\n        }\n        fn select_option(opt: String) {\n            selected.set(opt);\n        }\n        render {\n            let count_text = format!(\"Count: {}\", count.get());\n            quoin_render! {\n                div(class: \"flex flex-col gap-4 p-4 bg-gray-900 text-white\") {\n                    div(class: \"text-2xl font-bold\") { \"Quoin Render Demo\" }\n                    div { count_text }\n                    button(class: \"px-4 py-2 bg-blue-600 rounded-md\",\n                        on_click: move |_| increment()) {\n                        \"Increment\"\n                    }\n                }\n            }\n        }\n    }\n}"} />

Framework output:

- **GPUI** — a `struct DemoApp` with a `Render` impl.
- **Leptos** — `#[component] fn DemoApp() -> impl IntoView`.
- **Dioxus** — `#[component] fn DemoApp() -> Element`.

State fields declared in `state` become signals; plain Rust code inside `render` runs each render pass.

## Write trees with `quoin_render!`

The render syntax is JSX-like with named attributes, conditional blocks, and loops:

<Code lang="rust" code={"use quoin_macros::quoin_render;\n\nquoin_render! {\n    div(class: \"flex flex-col gap-4 p-4 bg-gray-900 text-white h-full\") {\n        div(class: \"text-2xl font-bold hover:text-blue-400\") { \"Hello\" }\n        if[show_details] {\n            div(class: \"p-2 bg-gray-800 rounded-md\") { details }\n        }\n        for[item in items] {\n            div(class: \"text-sm\") { item.name.clone() }\n        }\n        tabs(active: active_tab, on_click: move |i| set_active(i)) {\n            tab(index: 0, label: \"Tab 1\")\n            tab(index: 1, label: \"Tab 2\")\n        }\n        data_table(rows: people, striped: true) {\n            column(key: \"name\", label: \"Name\", render: |p: &Person| p.name.clone())\n            column(key: \"age\",  label: \"Age\",  render: |p: &Person| p.age.to_string())\n        }\n        clipboard_button(copy_text: \"Copied!\") { \"Copy\" }\n    }\n}"} />

Beyond `div` and `button`, the element vocabulary includes the rich components the emitters support per framework: `tabs`, `data_table`, `virtual_list`, `dropdown_menu`, `input`, `checkbox`, `radio`, `switch`, `slider`, `icon`, `badge`, `tooltip`, `progress`, `skeleton`, `scroll_area`, `separator`, and `styled_text`. Handlers receive [typed events](/reference/events/), so the same handler source compiles on all backends.

## Run side effects with `effect!`

`effect!` has a structured form with dependencies, a run closure, and optional cleanup:

<Code lang="rust" code={"use quoin_macros::effect;\n\neffect! { watch: [count], || println!(\"Count changed: {}\", count.get()) }\n\neffect! {\n    deps: [query],\n    run: || {\n        let data = fetch_data(&query.get());\n        results.set(data);\n    },\n    cleanup: || {\n        cancel_pending_request();\n    }\n}"} />

- **Leptos** expands to `create_effect` + `on_cleanup`.
- **Dioxus** expands to `use_effect` + `use_drop`.
- **GPUI** executes the run closure and calls cleanup when the effect is dropped.

## Bootstrap with `run_app!`

One line mounts your component:

<Code lang="rust" code={"run_app!(MyComponent);                            // GPUI with default window options\nrun_app!(MyComponent, window_opts: custom_opts);  // GPUI with a custom window\nrun_app!(MyComponent);                            // Leptos/Dioxus mount to body"} />

## Define reusable elements with `quoin_element!`

<Badge text="Advanced" variant="caution" />

`quoin_element!` declares a named custom element with typed props, rendered through a `quoin_render!` closure:

<Code lang="rust" code={"quoin_element!(\"my-widget\", { width: u32 }, |props| quoin_render! {\n    div { \"w\" }\n});"} />

<Aside type="note">
  The GPUI backend additionally re-exports the gpui-rsx escape hatch (`rsx!`, `rsx_strict!`, `#[component]`, …) under the `rsx` feature for GPUI-only subtrees inside `quoin_render!` render blocks — see the [styling guide](/guides/styling/#escape-hatch-for-gpui-only-subtrees).
</Aside>
