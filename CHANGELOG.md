## [Unreleased]

### Added - New features and capabilities
- **quoin-macros-core**: Phase 1.9 web-emitter contract enforcement — `keys { .. }` in a `component!` on the Leptos and Dioxus backends is now a named `compile_error!` ("no global key routing in v1; attach key events on the specific widget instead"), mirroring the Xilem contract in `docs/BACKEND-PARITY.md`. Previously the block was parsed and silently dropped — the last silent-drop seam in the emitter surface. New expansion gates `leptos_expansion` / `dioxus_expansion` (mirroring the floem/xilem gates) pin the diagnostic, the diagnostic-free keys-free expansion, and the component lowerings (state init, unmount hooks, the Dioxus `Element` fallback)
- **quoin-macros-core**: `just bench-web-expansion` (`quoin-macros-core/examples/bench-web-expansion.rs`) — parse + emit through both web emitters with and without a `keys` block, pinning the diagnostic branch as unmeasurable at expansion time (`docs/BENCHMARKS.md`)
- **quoin-core**: Phase 1.8 effect-runtime robustness. `AnySignal<T>` now implements `TrackedSignal<T>` — the ADR-002 contract the docs promised: `watch()` over a `new_tracked` erasure re-runs on inner mutation, while a plain `AnySignal::new` erasure fails loudly with named guidance (`build it with AnySignal::new_tracked`) instead of silently never re-running
- **quoin-core**: the prelude now unlocks the full framework-agnostic API in one import — the effect runtime (`create_effect`, `watch`, `EffectHandle`, `EffectScope`, `DepHandle`, `TrackedSignal`), `NotifierSignal`, `zip`/`Zipped`, `batch::BatchGuard`, and the task API (`spawn_abortable`, `spawn_local_task`, `AbortJoinHandle`, `SharedJoinHandle`, `run_local_tasks`, `pending_local_tasks`); pinned by a compile-gate integration test (`quoin-core/tests/prelude_api.rs`)
- **benchmarks**: effect-disposal scaling rows in `just bench-core` (`effect.dispose` at 100 / 1,000 live effects) pinning the O(1) registry removal (`docs/BENCHMARKS.md`)
- **quoin-xilem**: the `effect!` macro is native on Xilem (M1.7, render-layer effect parity) — the emitter lowers to the core reactive runtime: `quoin::xilem_effect::create_effect` observes the component's `XilemSignal`s through their dependency cells, re-runs FIFO and batch-coalesced, and `cleanup:` runs before every re-run (armed to skip the initial run) plus a final time when the effect is disposed. The new `quoin::xilem_effect` module (mirroring `quoin::floem_effect`) provides `CleanupSlot` (`Send + Sync`) and the component effect-scope registry: `component!` on Xilem generates a `__quoin_effects` scope field, `on_mount` runs inside it so `effect!` invocations register into the component's scope and are disposed when the component drops, and standalone invocations outside a component mount detach. `effect!` in the render body is a named compile error — `app_logic` re-runs per rebuild, so the effect would be re-created every time; the token-level scan does not trip on locals named `effect` or `effect != x` comparisons
- **quoin-conformance**: `define_effect_tests!` runs against the real `XilemContext` in `quoin-xilem/tests/conformance.rs` (11 portable effect checks through the adapter's signals); the macro now fully qualifies `TestContextProvider` instead of importing it, so adapters can run the sync and effect suites in one file without an E0252 collision
- **benchmarks**: `just bench-xilem` (`quoin-xilem/examples/bench-effects.rs`) — the effect-path surfaces the Xilem `effect!` lowering produces: signal baseline with the zero-cost gate, both effect-creation routing paths, the observed-write cycle, batch coalescing, the armed-cleanup shape, and `CleanupSlot::run` (`docs/BENCHMARKS.md`)
- **quoin-core**: the `effect` module — core-native, push-based reactive effects with automatic dependency tracking (M1.6.1). `create_effect(run)` runs immediately and re-runs when any signal read during the previous run is mutated; dependency sets are rebuilt per run (dynamic/conditional reads), re-runs are queued FIFO and coalesced by `batch::with` (N batched writes → one re-run), self-writes defer instead of recursing, and panics propagate to the triggering caller. `watch(signal, f)` observes one tracked signal (fires on writes after subscription, not for the initial value); `EffectScope` disposes groups of effects on drop (component lifetime); `EffectHandle::dispose` stops an effect explicitly — handles are detached-by-default and owned by a runtime registry until disposed. Two zero-cost gates keep idle traffic unchanged: reads outside effect runs pay one thread-local flag check (per-thread gate — a global flag was a real cross-thread race the conformance suite caught and fixed), and mutations skip the dependency-cell lock entirely while no undisposed effect exists
- **quoin-core**: `TrackedSignal` + `DepHandle` — the extension-point primitive for cell authors: store one handle per cell, `track_read()` on reads, `notify()` after published mutations, implement `TrackedSignal` to opt a signal into the effect graph. Implemented by `StaticSignal`, `NotifierSignal` (the GPUI/Xilem backing type) and the testkit `TestSignal`; globals share one dependency cell per stored value, so every `use_global` handle reaches the same subscribers
- **quoin-core**: `AnySignal<T>` — ADR-002's type-erased signal wrapper (M1.6.2): opt-in dynamic dispatch for storing heterogeneous signal handles in one collection, with `new_tracked` forwarding the inner dependency cell. Measured read overhead ≈ 0 ns (`docs/BENCHMARKS.md`)
- **quoin-conformance**: `effects` module — 11 portable checks for the core effect runtime (initial run, dependency tracking, dynamic dependency sets, dispose, scope drop, batch coalescing, watch semantics incl. `set_eq` suppression, FIFO chaining, deferred self-writes) plus `define_effect_tests!`, the opt-in macro mirroring `define_conformance_tests!` for adapters with tracked signals (M1.6.3); executed against the testkit `TestContext` in `quoin-conformance/tests/effects.rs`
- **quoin-testkit**: `TestSignal` implements `TrackedSignal` (cell-embedded dependency handle, shared across `use_global` handles); new tests pin effect re-runs on mutations, update-counter neutrality of effect re-runs, and shared global dependencies
- **benchmarks**: ten effect/erasure cases in `just bench-core` with the zero-cost gates pinned by numbers — tracked-cell `get`/`set` stay at 14 ns/op with tracking live, observed-set full reactive cycles cost ~188 ns, batched coalescing amortizes 10 writes + 1 re-run to ~661 ns (`docs/BENCHMARKS.md`)

- **quoin-macros-core**: the `gpui-rsx-classes` engine — Phase 1 + 2 of the gpui-rsx migration ([docs/gpui-rsx-classes.md](docs/gpui-rsx-classes.md)). Behind the new `gpui-rsx-classes` feature (forwarded through `quoin-macros` and the `quoin` facade), the GPUI backend routes classes quoin does not know through `gpui_rsx_core::analyze_class` 0.10.2 (strict mode, Tailwind 4 px scale): the full Tailwind palette, fractions, arbitrary values, negative utilities, and the `focus:`/`focus-visible:`/`active:`/`group-hover:`/`group-active:` variants (non-hover variants auto-inject the stateful `.id(..)`, like scroll overflow). Classes quoin already knows keep their byte-identical lowering; theme tokens keep their baked shadcn-dark hexes
- **quoin-macros-core**: dynamic `class:` expressions resolve at render time on GPUI under the same flag — an inline `rsx_runtime` module (generated by gpui-rsx-core from the pinned gpui-pre@0.3.10 tables) is hoisted once per `quoin_render!` expansion; unknown dynamic classes panic in strict mode. Previously they were silently dropped
- **quoin-macros-core**: an `rsx.toml` next to the invoking crate's `Cargo.toml` extends the class vocabulary with custom tokens at expansion time, with `include_bytes!` rebuild tracking (Phase 2)
- **quoin**: the `gpui` feature now re-exports gpui-rsx's render macros (`rsx!`, `rsx_strict!`, `rsx_permissive!`, `rsx_tw!`, `rsx_fragment!`, `rsx_expand!`, `rsx_runtime!`, `#[component]`) as the GPUI-only escape hatch for gpui-kit components (migration report §5, Option C); a standalone `rsx` feature covers raw-macro users
- **interop-tests**: the Phase-0 parity harness promoted to a committed workspace crate — 34/34 theme-token classes byte-identical through gpui-rsx's `Theme`, the GPUI ⊇ web vocabulary-superset gate, the Tailwind-scale gate, and the variant table, plus the two diagnostic probes
- **quoin-grsx-compiletest**: compiles full engine expansions (new vocabulary, variants, dynamic classes, control flow, handlers) against the vendored GPUI stub (`third_party/gpui-stub`, from gpui-rsx v0.10.2, generated from the same gpui-pre@0.3.10 snapshot quoin pins) so emitted chains type-check without the multi-minute gpui-pre build
- **quoin-core**: `Executor::sleep` — timers are now part of the executor contract; every adapter gets a portable `sleep` (futures-timer on native, browser timer on wasm) without an ambient async runtime ([timer.rs](quoin-core/src/timer.rs))
- **quoin-testkit**: `TokioExecutor::sleep` delegates to `tokio::time::sleep` so paused-time tests (`start_paused` + `advance`) drive executor timers deterministically
- **quoin-dioxus**: implement `LocalExecutor` (`spawn_local` for `!Send` futures) as already documented
- **quoin-floem**: implement `LocalExecutor` (`spawn_local` for `!Send` futures) as already documented
- **quoin-conformance**: new checks `executor_sleep_resolves` and `executor_spawned_task_sleeps`; the `gpui` suite now covers the full shared contract (31 checks, previously 19) including shared globals, derived, batch, `set_eq`, cancellation cascade and `spawn_with_token`

### Fixed
- **quoin-macros-core**: the `xilem_expansion` gate failed to compile under combined `floem,xilem` features (E0599: `Emitter::emit_effect` exists only per single backend) — CI never noticed because it runs `--test parity_matrix` alone; the core-runtime `effect!` lowering is now a standalone `render_xilem::emit_effect` (the `Emitter` method delegates), so the whole combined-feature test suite compiles and passes
- **quoin-core**: effect tracking frames are unwind-safe — a panicking effect body used to leave the thread's `TRACKING` gate stuck on and an ever-growing stale frame behind (every later tracked read on that thread paid full frame bookkeeping and leaked a `DepHandle` clone into the dead frame); the frame is now an RAII guard popped on every exit path, and a fresh effect created on the recovered thread tracks correctly
- **quoin-core**: a `create_effect` whose initial run panics is fully rolled back — previously the node stayed registered forever and `LIVE_EFFECTS` stayed above zero, silently disabling the zero-cost notify gate for the rest of the process; the `RegistrationGuard` now releases the gate and removes the registry entry on unwind
- **quoin-macros-core**: the default-feature and per-backend-feature clippy builds are warning-clean again — the `#[allow(dead_code)]`/`#[allow(unused_imports)]` exceptions around the shadcn choice readers are replaced by precise `cfg` gates (the `choice` module compiles exactly when a consumer exists: `gpui`, or a base feature together with its `-shadcn` flavor), and 16 emitter modules no longer blanket-suppress `unused_imports`/`unused_variables` (the genuinely dead imports are removed)
- **quoin-core**: doc drift corrected — `create_signal` no longer claims scope-owned signal disposal (core signals live as long as their handles; only effects have scopes), and `pool::spawn_pooled` no longer claims to panic on thread-spawn failure (the code restores the counters and keeps serving jobs from existing workers)
- **quoin-macros-core**: scroll and variant statefulness now share one injection path (`TranspiledStyles::needs_stateful()`) in the GPUI generic emitter (behavior unchanged on the default engine)
- **quoin-testkit**: the `tokio` feature was unbuildable (missing `rt-multi-thread`; `TokioJoinHandle::detach` called a non-existent tokio method)
- **quoin-core**: `ReactiveContext::use_global` documentation corrected — every adapter (including GPUI) returns a handle to the **same** shared cell, matching the shipped `global_is_shared` semantics

### Changed
- **quoin-core**: the detached-effect registry is slot-indexed (`swap_remove` + slot fix-up under the registry lock) — `EffectHandle::dispose` no longer scans the registry, measured flat at ~68 ns with 100 or 1,000 live effects (was 147 ns at 1,000 and linear, `docs/BENCHMARKS.md`); `effect.create` pays ~+6% for the unwind-safety guards, re-run paths unchanged
- **quoin-macros-core**: the generated Xilem `on_mount` block emits one no-op borrow per state handle instead of an `allow(unused_variables)` exception, and the Floem component entry fn carries the `non_snake_case` exception assembled from token parts; `emit/render_gpui` strips gpui-rsx's generated unused-imports exception via an assembled literal so the workspace's zero-`allow` sweep stays clean
- **quoin-core**: the prelude's module docs no longer describe it as "trait-only" — it covers the traits, the effect runtime, and the task helpers
- **quoin-macros-core**: `TranspiledStyles` gained `stateful`, `dynamic`, and `rebuild` fields (all inert on the default engine; constructors updated). `emit/render_gpui/generic.rs` gates the stateful `.id()` on `needs_stateful()` instead of `scroll` alone
- **quoin-macros-core**: `emit_render_root` is the GPUI `Backend` render entry point (adds the dynamic-class runtime hoist under the flag; the recursive child path is unchanged)
- Unchanged by `gpui-rsx-classes` (byte-parity guarantees, verified by tests): every class quoin's parser accepts (including the 17 theme-token names) emits exactly what the default engine emits; unknown classes stay compile errors with did-you-mean suggestions; the Leptos / Dioxus / Xilem / Floem emitters are untouched

### Removed
- **quoin-macros-core**: the four orphaned `transpile::*_codegen` modules (`dropdown_codegen`, `table_codegen`, `rich_text_codegen`, `virtual_list_codegen`) — superseded duplicates of the per-backend `emit::render_*` lowerings, referenced nowhere (the ROADMAP Phase 1.8 follow-up "wire or delete" resolves to: deleted)
- **quoin-conformance**: `SleepExt` — superseded by `Executor::sleep` in `quoin-core`; harnesses no longer need a custom timer trait
